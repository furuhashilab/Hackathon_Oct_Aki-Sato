# 論文の地質図を Maplat で実際の地図に乗せ、京都天然砥石の砥石山と丹波帯の地層の関係を調べる

Aki Sato（FuruhashiLab）／ 10月 FOSS4G Hiroshima / SotM Asia OSAKA 振り返りハッカソン

---

## I. Introduction（背景と目的）

### 背景
- 京都の天然砥石（鳴滝砥石）の母岩は **砥石型珪質頁岩（中生代三畳紀）** で、**丹波帯Ⅰ型地層群の最下部の岩相** とされる。分布は **おもに高雄から北嵯峨にかけて** で、表面には **コノドント** の微化石が見られる（京都府 RDB2015 soi0080, soi0081）。
- 砥石山の位置と地質の関係は、論文の地質図（図-2(a)：井本ほか 1989・木村 2000 に加筆。Type 1 チャート／Type 2 砕屑岩、断層、⚒ 砥石山）に描かれている。
- しかし論文の図は **紙面上の絵** であり、そのままでは実際の地図と重ねたり、砥石山と地層の位置関係を数えたりできない。
- 既存の砥石マップ（例：tj-culture の砥石マップ）は「**どこに砥石山があるか**」を示すが、「**なぜそこで採れるのか**」という地層との関係は扱っていない。

### 参考にした発表と、使った新しい技術
- **参考発表**：大塚恒平「Bringing Old Maps & Illustrated Maps to the Web: 10 Years of Maplat and Turning Misalignment into Innovation」（FOSS4G Hiroshima 2026, 9/2）
- **Maplat**：古地図や絵地図を、**元の絵を歪めずに** 実際の地図と結びつける技術。対応点（GCP）から作る TIN（三角網）で、図の座標と実座標を **双方向に** 変換する。

### なぜ Maplat を使ったのか
1. 論文の図は、縮尺バー・方位・地名の注記が互いに完全には一致しない（Results 参照）。一律のアフィン変換では誤差が残るが、Maplat の TIN は **対応点を必ず通る非線形変換** で、対応点を増やすほど局所的に合わせ込める。
2. **図を一次資料として歪めずに残したまま**、実際の地図と行き来できる。図の上で ⚒ を確かめ、同じ点を実際の地図で見る、という検証が可能になる。
3. 変換ライブラリ（`@maplat/tin`）と表示ライブラリ（`@maplat/core`）が分かれているので、**同じ変換をデータ処理にも表示にも使える**。

### 目的
論文の図-2(a) を Maplat で実座標に結びつけ、図から地層の帯と砥石山を取り出して **階層化** し、
「砥石山は Type 1（チャート・珪質岩）の帯とどんな位置関係にあるか」「砥石山の記録がない Type 1 の帯（未記録区間）はどこか」を示す。

## M. Methods（方法）

```
論文 図-2(a)（画像）
  │ tools/extract.py   色と形で抽出（OpenCV）
  ├─ Type 1（オレンジ）/ Type 2（青）の帯 … ポリゴン（画素座標）
  └─ ⚒ 砥石山 … 点（画素座標）
        │ tools/georef.mjs   @maplat/tin（対応点 data/gcps.csv）
        ▼
  実座標（緯度経度）の帯・砥石山 ＋ maps/fig2a.json（Maplat の地図定義）
        │ tools/analyze.py   空間結合・距離（Shapely）
        ▼
  units.geojson / mines.geojson / summary.json ＋ data/hierarchy.json（階層）
        │
  index.html … ① Maplat（論文の図）＋ ② MapLibre（実際の地図）
```

1. **抽出**：図-2(a) を 3 倍に拡大し、凡例の色（Type 1 チャート＝オレンジ、Type 2 砕屑岩＝青）で塗り分けを取り出してポリゴン化した。⚒ 記号や文字で生じる小さな穴は地層の一部として埋めた。⚒ は「色の付いた地層の中にある明るい小さな点」として検出し、2 本のつるはしが分かれた点は 20px 以内をまとめた（21 か所）。
2. **位置合わせ（Maplat）**：
   - 基準：**20万分の1地質図幅「京都及大阪（第2版）」**（産総研）。図郭（東経135°〜136°、北緯34°40′〜35°20′）の画素位置を測り、経緯度との対応を決めた（縦横の縮尺が 9.55 px/km で一致することを確認）。
   - 20万分の1のチャート（サーモン〜オレンジ色。凡例では「基底に珪質粘土岩を伴うチャート」）と、論文の図の Type 1 チャートが **最もよく重なる** 縮尺・回転・位置を総当たりで探した（`tools/register200k.py`、重なりの指標は F 値）。
   - 求めた変換から図の四隅と中心を対応点にし（`data/gcps.csv`）、`@maplat/tin` で TIN を作って帯と砥石山を実座標へ変換した。同じ TIN を `maps/fig2a.json` に書き出し、`@maplat/core` で図そのものを表示した。20万分の1地質図の切り出しも、図郭の四隅を対応点にして Maplat の地図にした（`maps/gsj200k.json`）。
   - 当初は図中の地名注記（Atago-san・Takao・Kiyotaki）3点を対応点にしたが、後述のとおり精度が低かったため置き換えた。
3. **階層化**：丹波帯 → Type 1／Type 2 地層群 → 砥石型珪質頁岩（三畳紀・コノドント）→ 砥石山 → 層・称号、と構造（保津川アンチフォーム・断層）を `data/hierarchy.json` にまとめた（出典つき）。
4. **分析**：凡例の灰色「Type II」（Ⅱ型地層群）の範囲も抽出し、各砥石山がⅠ型（Type 1・Type 2）とⅡ型のどちらにあるかを数えた。各砥石山について、乗っている帯と、Type 1 の帯までの距離を求めた。比較として、地質図の範囲内にランダムに置いた 5,000 点が Type 1 から 300m 以内に入る割合を求めた。Type 1 の帯のうち、300m 以内に砥石山がないものを **未記録区間** とした。
5. **OSM との答え合わせ（Overpass API）**：ページを開くたびに、Overpass API で図の範囲内の OpenStreetMap の地物（石切場 `landuse=quarry`、鉱山跡 `historic=mine`、坑口 `man_made=adit|mineshaft`、露頭 `geological=outcrop`、名前に「砥」を含むもの）を取得し、図から抽出した砥石山から 500m 以内に OSM の地物があるかを数える。論文・産総研とは**独立に作られた**データで位置合わせを確かめるためで、OSM に砥石山が追加されれば、ページは自動で最新の状態を反映する。
6. **検証**：実座標に変換した砥石山を Maplat に渡し、Maplat が逆変換して図の上に描いたピンが、元の ⚒ 記号に重なるかを目で確認した。

## R. Results（結果）

### 1. 位置合わせ
| 方法 | 縮尺 | 回転 | 20万分の1との重なり（F値） |
|---|---:|---:|---:|
| 図中の地名注記 3 点（当初） | 108 px/km | −9.2° | 0.153 |
| **20万分の1のチャートとの重なり最大化（採用）** | **75 px/km** | **0°** | **0.466** |

- 採用した縮尺 75 px/km は、**論文の図の縮尺バー（2 km ≒ 150 px）から測った値と一致** し、回転 0° は図の **方位記号（北が上）** と一致した。3 つの独立した手がかり（20万分の1地質図・縮尺バー・方位記号）が同じ答えになった。
- 図は東経 135.568°〜135.713°、北緯 35.001°〜35.108°（約 13 × 12 km）に乗った。高雄付近の大きなチャートの塊が、20万分の1のオレンジ色の塊と重なる（`docs/check_registration_200k.png`）。
- Maplat の図の上では、逆変換したピンが ⚒ 記号に重なった（図 → 実座標 → 図の往復で位置がずれない）。
- OSM との答え合わせは閲覧時に取得するため、結果はページの「OSM との答え合わせ」欄に表示される（作成環境からは Overpass API に接続できず、事前の集計はしていない）。

### 2. 砥石山と地層
| 項目 | 値 |
|---|---:|
| 図から抽出した砥石山 | 21 か所 |
| **Ⅰ型地層群の範囲にある砥石山** | **21 か所（Ⅱ型の範囲は面積の 12% だが 0 か所）** |
| Type 1 の帯の上にある砥石山 | 4 か所（19%。Type 1 の面積の割合は 17%） |
| Type 1 の帯から 300m 以内の砥石山 | 9 か所（43%） |
| 比較：ランダムな地点が Type 1 から 300m 以内に入る割合 | 36% |
| 砥石山から Type 1 までの距離（中央値） | 340 m |
| Type 1 の帯：砥石山あり／なし（未記録区間） | 6 ／ 32 |
| 未記録区間の面積 | 719.7 ha |

- 砥石山は大きく 2 か所に集まる。南東の集まりは京都盆地の縁（高雄〜梅ヶ畑〜鳴滝付近）で、「鳴滝砥石はおもに高雄から北嵯峨」という記述（京都府 RDB）と位置が合う。もう一つは愛宕山の北側。

## D. Discussion（考察）

### 砥石山と地層の関係
- **砥石山はすべてⅠ型地層群の範囲にあり、Ⅱ型には無かった**。砥石型珪質頁岩は「Ⅰ型地層群の最下部」（井本ほか 1989；京都府 RDB）なので、これと合う。ただし、ランダムに置いても 21 か所すべてがⅠ型に入る確率は約 7%（0.883²¹）あり、はっきり有意とは言えない。
- 一方、**Type 1 チャートの帯との距離では、ランダムな地点との差がほとんど無かった**（300m 以内：43% 対 36%）。当初（地名 3 点の位置合わせ）では「帯の縁に集まる」ように見えたが、正しく位置合わせし直すと支持されなかった。**位置合わせの誤差が、そのまま見かけの結論を作ってしまう** ことが分かった。
- 砥石型珪質頁岩は厚さ数 m〜数十 m の薄い層で、5万分の1〜20万分の1の地質図ではチャートと一緒に塗られている。「チャートの帯」という粗い単位では砥石層の位置まで絞れない。**Ⅰ型かⅡ型か** という構造の単位のほうが効いている可能性がある。

### 新規性
- 既存の砥石マップは「砥石山の位置」の地図。本ツールは **論文の地質図を Maplat で実座標に結びつけ**、砥石山を **地層の帯・地質の階層** と結びつけて「**なぜそこで採れるか**」を数えられるようにした。
- 図を歪めずに残したまま実際の地図と行き来できるので、**一次資料（論文の図）に戻って検証できる**。
- **論文の図・20万分の1地質図・地理院地図という縮尺も作り方も違う地図を、Maplat で同じ実座標につなぎ**、同じ砥石山が各図のどこにあたるかを切り替えて比べられる。位置合わせ自体も、20万分の1との重なりという客観的な指標で決めた。
- 「Type 1 の帯なのに砥石山の記録がない区間（未記録区間）」を地図上で示した。廃山・絶産の調査や、聞き取りの対象地を絞る材料になる。

### OSM について
- OSM の地物は、航空写真からトレースされたものなら位置は数 m〜十数 m と正確だが、山中の採掘跡・坑口は登録されていないことが多い。**OSM に無い ≠ 存在しない** ので、「近くに OSM 地物がある砥石山」は位置合わせの裏付けにはなるが、無いことは反証にならない。
- 逆に、現地調査で砥石山を OSM に登録していけば、このページの答え合わせが自動で充実していく。オープンデータで「一次資料（論文）」「公的な地質図（産総研）」「市民が作る地図（OSM）」をつなぐ形になる。

### 限界
1. **位置合わせの精度**：基準にした20万分の1地質図の画像は 1 px ≒ 100 m で、これより細かい精度はない。両図の塗り分けの違い（縮尺・編集）もずれの原因になる。
2. **図の解像度**：使った論文の図は低解像度で、座標の目盛りが読めない。⚒ と IC 値の地点を取り違えている可能性がある。
3. **層・称号が未入力**：京都天然砥石組合編（2003）などから、砥石山ごとの層と称号を入れる必要がある。
4. **未記録区間 ≠ 有望地**：記録がないだけで、砥石層がないのか、まだ採られていないのか、調査されていないのか（破線内は未調査地域）は区別できない。

### 今後
1. 5万分の1地質図幅「京都西北部」（井本ほか 1989）本体を基準に加え、位置合わせの精度を上げる。論文の図の座標目盛り（平面直角座標系 VI 系）が読める高解像度版があれば、それを対応点にする。
2. 図-1（傾斜量図）の砥石層の分布域（白線）も、同じく Maplat で取り込む。
3. 砥石山に名前・層・称号・稼働状況（例：中山は絶産）を入れて、階層の下の段を埋める。
